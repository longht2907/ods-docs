## 1. Khi nào dùng bài này?

Áp dụng khi bản ghi cuộc gọi trên Portal **đã hiển thị biểu tượng Ghi âm** nhưng người dùng không thể nghe hoặc tải file:
- Bấm vào nút Play thì trình phát âm thanh quay tròn liên tục (loading spinner) hoặc báo lỗi `Error loading media`.
- Bấm nút Tải xuống (Download) báo lỗi `403 Forbidden`, `404 Not Found`, hoặc tải về file rỗng `0 byte`.
- File âm thanh vẫn phát, thanh thời gian vẫn chạy nhưng loa hoàn toàn không có tiếng (im lặng).

### Phân biệt với các sự cố gần giống
- **Cuộc gọi hoàn toàn không có biểu tượng nút Ghi âm**: Xem [Thiếu file ghi âm](/internal/ai-contact-center/runbooks/recordings/missing-recordings).
- **Điện thoại viên đàm thoại trực tiếp bị mất tiếng**: Xem [Âm thanh một chiều / rè](/internal/ai-contact-center/runbooks/calls/one-way-audio).

## 2. Tiếp nhận và kiểm tra nhanh

L1 cần phân loại nhanh theo phạm vi lỗi:

| Hiện tượng quan sát | Nhận định kỹ thuật ban đầu | Hướng xử lý L1 |
| :--- | :--- | :--- |
| **Chỉ 1 máy tính bị lỗi, máy khác cùng tài khoản nghe bình thường** | Do trình duyệt bị chặn âm thanh, tab bị Mute hoặc driver âm thanh máy tính. | Kiểm tra cài đặt trình duyệt và âm lượng máy tính. |
| **Bấm Nghe được nhưng nút Tải xuống bị mờ hoặc báo 403** | Tài khoản chỉ được cấp quyền *Nghe trực tuyến*, bị chặn quyền *Tải file về máy*. | Giải thích chính sách phân quyền bảo mật cho khách hàng. |
| **Báo lỗi 403 / 404 trên hàng loạt file ghi âm** | Đường link ký số bảo mật (Signed URL / Presigned URL) bị lỗi cấu hình hoặc hết hạn. | **Chuyển cấp L2 / Hạ tầng Storage.** |
| **Tải về file 0 byte hoặc mở file báo lỗi hỏng định dạng** | File âm thanh trên máy chủ lưu trữ bị lỗi trong quá trình nén/upload. | Chuyển cấp L2 để kiểm tra file gốc trên Storage. |

## 3. Thông tin cần hỏi khách hàng

Thu thập thông tin theo 2 nhóm:

### Thông tin tối thiểu bắt buộc
1. **Mã cuộc gọi mẫu (`[CALL_ID]`):** Cuộc gọi cụ thể đang không nghe hoặc tải được?
2. **Triệu chứng chính xác:** Nút Play quay liên tục, báo mã lỗi gì, hay tải về file không mở được?
3. **Phạm vi lỗi:** Chỉ 1 file này bị hay tất cả các file ghi âm khác đều bị?
4. **Trình duyệt & Thiết bị:** Khách hàng đang dùng trình duyệt gì (Chrome, Edge, Safari, Firefox)?

### Thông tin bổ sung (Hỏi khi cần)
- Người dùng khác có cùng quyền trong công ty có mở nghe được file đó không?
- Máy tính của nhân viên có phát được âm thanh từ các trang web khác (như YouTube) bình thường không?

## 4. Checklist kiểm tra an toàn cho L1

Kỹ sư L1 thực hiện kiểm tra quan sát (Read-only) theo bảng sau:

| Bước | Thực hiện | Cách kiểm tra | Kết quả bình thường | Kết quả bất thường & Hướng xử lý |
| :--- | :--- | :--- | :--- | :--- |
| **1. Kiểm tra trạng thái Mute của Tab trình duyệt** | Khách hàng | Nhìn lên thanh tab trình duyệt xem có biểu tượng chiếc loa bị gạch chéo không | Loa không bị tắt | Tab đang bị Mute: Chuột phải vào tab chọn *Bật âm thanh trang web (Unmute site)*. |
| **2. Thử nghiệm trên Cửa sổ ẩn danh** | Khách hàng | Mở cửa sổ ẩn danh (Incognito), đăng nhập Portal và nghe thử | Nghe phát âm thanh bình thường | **Do xung đột Extension trình duyệt**: Tắt các tiện ích chặn quảng cáo/download. |
| **3. Kiểm tra phân quyền Download của tài khoản** | L1 tra cứu | Xem nhóm quyền (Role) của tài khoản khách hàng trên Portal | Tài khoản có quyền `Download Recording` | Chỉ có quyền `Play`: Khách hàng không được phép tải theo chính sách công ty họ. |
| **4. Kiểm tra mã lỗi mạng trên Developer Tools (F12)** | L1 / Khách hàng | Bấm F12 -> Tab *Network* -> Bấm nút Play/Download xem request file media | Trả về mã HTTP `200` hoặc `206 Partial Content` | Trả về mã `403 Forbidden` hoặc `404 Not Found`: Link ký số hoặc file trên S3 bị lỗi. |
| **5. Nghe thử file trên tài khoản L1 (Nếu được phép)** | L1 thực hiện | Dùng công cụ kiểm tra nội bộ mở nghe thử 5 giây | Âm thanh phát rõ ràng | File nội bộ cũng báo lỗi tương tự: Lỗi từ cụm máy chủ lưu trữ. |

## 5. Hướng xử lý cơ bản (Ít rủi ro trong quyền hạn L1)

1. **Khắc phục lỗi trình duyệt chặn Autoplay:**
   - Trên Chrome/Edge: Bấm vào biểu tượng ổ khóa cạnh URL -> Chọn *Cài đặt trang web (Site settings)* -> Mục *Âm thanh (Sound)* chọn **Cho phép (Allow)**.

2. **Giải thích về quyền tải file bảo mật:**
   - Nếu nhân viên chỉ nghe được mà không tải được: Giải thích đây là chính sách bảo mật chống rò rỉ dữ liệu của công ty họ, chỉ tài khoản cấp Quản lý (Admin/Manager) mới có nút Tải file về máy.

3. **Xóa Cookie và Cache trang web:**
   - Hướng dẫn người dùng xóa dữ liệu đệm của trang Portal để trình duyệt tải lại phiên bản trình phát âm thanh mới nhất.

## 6. Khi nào dừng và chuyển cấp?

Dừng xử lý và chuyển ticket lên L2 / Kỹ sư Hạ tầng Lưu trữ khi:

- [ ] **Mã lỗi 403 / 404 diện rộng:** Hàng loạt file ghi âm không thể phát hoặc tải được do lỗi chứng thực với Cloud Storage.
- [ ] **File tải về có dung lượng 0 byte hoặc bị hỏng định dạng:** Nghi vấn lỗi tiến trình nén file MP3 từ bản ghi WAV thô.
- [ ] **Thanh âm thanh chạy bình thường nhưng hoàn toàn không có tiếng:** Cần kiểm tra xem luồng RTP của cuộc gọi có bị mất gói tin âm thanh ngay từ lúc đàm thoại hay không.
- [ ] **Lỗi hết hạn chứng chỉ bảo mật Storage:** Tên miền lưu trữ media bị lỗi SSL hoặc cấu hình CORS chặn trình duyệt phát âm thanh.

## 9. Xác nhận khôi phục

1. **Phát thử nghiệm trên trình duyệt:** Bấm nút Play, xác nhận thanh tiến trình di chuyển mượt mà, âm thanh phát rõ ràng qua tai nghe/loa.
2. **Tải thử file về máy:** Bấm nút Download, xác nhận file tải về đầy đủ dung lượng (dung lượng > 0 KB), mở file bằng trình phát nhạc chuẩn (Windows Media Player, VLC) nghe bình thường.
3. **Xác nhận từ người dùng:** Nhận được phản hồi xác nhận nghe tốt từ phía khách hàng.
